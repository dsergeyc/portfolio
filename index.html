Case Study 01

Checkout
Redesign
Problem
Checkout was fragmented.
  • Teams built similar flows independently — no shared UI
  • Inconsistent specs, high cost to maintain
  • Revenue-critical journeys slowing Growth experimentation
  • 12% of cancels traced to a wrong email at checkout — users locked out of accounts they paid for. $8.3M/year in refunds.
Before
The old checkout experience.
Step 1 — Email
Step 2 — Payment
Step 3 — Confirmation
Hypothesis
A guided, one-page checkout will reduce drop-off and increase conversion.

My role: Started as Design Lead, transitioned to Manager mid-program. Led a designer on this program while partnering with PM, Eng, PMM, and Growth.

Key Decisions
Three bets that shaped the program.
Test first. Platform later.

Validate the concept before investing in full S2 component infrastructure. Let the experiment justify the platform.

Incrementally adopt the new design system.

System mid-migration from v1 to v2 — not all components were React-ready. Move forward with a plan to close gaps post-validation rather than wait.

Don't make teams wait for the platform.

Product teams kept shipping features while we built the reusable foundation in parallel — so no one was blocked waiting for infrastructure to be ready.

Case Study 03
Mobile
Optimization
for Plans Page
Problem
Mobile users were hitting friction before they even reached checkout.
  • High mobile traffic with room to improve — conversion opportunity on a desktop-first experience
  • Engineering backlog made small UI iterations slow and costly
Opportunity

Fix the mobile experience fast — without waiting in the engineering queue.

Approach
Designer and PM ship code. Engineer reviews. Production.
Step 1 — Setup
Local repo, not a design file

Designer and PM cloned the checkout repository. Engineer walked them through terminal setup and local environment — no design-only handoff.

Step 2 — Build
AI-assisted code changes

Designer used Claude to prototype the mobile layout directly in code — iterating on real markup, not mockups. PM contributed copy and logic changes inline.

Step 3 — Ship
Engineer reviews, pushes to production

Changes submitted as a pull request. Engineer reviewed for quality and safety, then merged. Designer owned the outcome end-to-end.

Demo
Prototype built in Claude by the designer.
Process
What made this different.
Before
Design → Handoff → Engineering queue → Production

Weeks of back-and-forth. Designer loses control after handoff. Small changes take disproportionate effort.

After
Designer + PM → Code → Review → Production

Designer owns the full loop. AI handles the gap between design thinking and implementation. Engineer focuses on review, not translation.

Why it matters

This is the first project where our team shipped production code without a traditional design handoff. It's a model we're expanding across the team.
